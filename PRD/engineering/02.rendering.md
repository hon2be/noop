# 02. 터미널 렌더링 원리

## 터미널의 본질

터미널은 **문자 격자(character grid)** 다. 모든 "그래픽"은 이 격자의 어느 셀에 어떤 문자를 어떤 색으로 놓냐의 문제.

```
(0,0)→ 열(col)
↓
행(row)   0    1    2    3    4
  0     [ H ][ e ][ l ][ l ][ o ]
  1     [ W ][ o ][ r ][ l ][ d ]
  2     [   ][   ][   ][   ][   ]
```

---

## 레이어 1 — ANSI 이스케이프 코드

터미널은 바이트 스트림을 받는다. 특정 패턴(`ESC [ <숫자> <문자>`)은 출력이 아닌 **명령**으로 해석된다.

```python
ESC = "\033"  # = \x1b

# 커서 이동
print(f"\033[5;10H")         # 5행 10열로 이동

# 색상
print(f"\033[31m빨간글씨\033[0m")   # 빨강 → 리셋

# 화면 지우기
print(f"\033[2J")            # 전체 지우기
print(f"\033[K")             # 현재 줄 끝까지

# 커서 표시/숨김
print(f"\033[?25l")          # 숨기기
print(f"\033[?25h")          # 보이기
```

## 레이어 2 — 더블 버퍼링

매 프레임 전체를 지우고 다시 그리면 깜빡임 발생.

```
❌ 나이브한 방식
  지우기 → 그리기 → 지우기 → 그리기
           └─ 지운 순간 빈 화면 노출 = 깜빡임

✅ 더블 버퍼링 (curses)
  버퍼 B에 조용히 그림 → refresh() 호출
  → curses가 이전 버퍼 A와 diff
  → 바뀐 셀만 ANSI 코드로 터미널에 전송
```

```python
stdscr.clear()              # 버퍼에만 지움 (화면 아님)
stdscr.addstr(0, 0, "안녕") # 버퍼에만 씀
stdscr.refresh()            # ← 이때 처음으로 화면 반영
```

## 레이어 3 — 문자 선택 (ASCII Art 원리)

문자의 **밀도(density)** 차이로 명암 표현:

```
어둡다 ←─────────────────────── 밝다
█  ▓  ▒  ░  #  @  %  +  -  .  (공백)
```

박스 드로잉 문자가 TUI의 핵심 재료:
```
─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼   (단선)
═ ║ ╔ ╗ ╚ ╝ ╠ ╣ ╦ ╩ ╬   (이중선)
━ ┃ ╾ ╼ ┿ ╋              (굵은선)
```

## 우리 게임 렌더 파이프라인

```
게임 State
    ↓
render() — 16ms마다 호출
    ├── stdscr.clear()
    ├── 헤더 addstr()
    ├── 테두리 addstr()
    ├── 게임 콘텐츠 addstr()
    └── 푸터 addstr()
    ↓
stdscr.refresh()
    ↓
curses diff → 바뀐 셀만 ANSI 전송
    ↓
터미널 화면 업데이트
```

## ANSI 없이 직접 그리기 (원리 이해용)

```python
import sys

def goto(y, x):
    sys.stdout.write(f"\033[{y+1};{x+1}H")

def box(y, x, h, w):
    goto(y, x);     print("┌" + "─"*(w-2) + "┐")
    for i in range(1, h-1):
        goto(y+i, x); print("│" + " "*(w-2) + "│")
    goto(y+h-1, x); print("└" + "─"*(w-2) + "┘")

sys.stdout.write("\033[2J\033[H")  # 클리어
box(2, 5, 6, 30)
goto(4, 7)
print("Hello Terminal!")
sys.stdout.flush()
```

curses는 이 위에 키 입력 처리, 색상 관리, diff 렌더링을 얹은 것.
